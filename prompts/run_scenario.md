## 任务：跑「${scenario}」——路书走到哪，就从哪接着勘

路书记的是「这条流程已经被勘明白到第几步」。可能一步都没有（全新场景），可能只记到一半
（上次没跑完），也可能是全部。三者是同一件事的不同位置，**不是几种模式**，你每次都做同一件事：

1. **照着已记的步骤走。** 每步先按路书里的**锚点**确认元素在不在，在就直接操作，
   **不要重新思考"该点哪"**——这些步骤是前人真走通过的，重新推理一遍纯属浪费。
   写「【参考】某原子」的，那个原子在 `atoms/<名字>.md`，需要时用 read_resource 读，
   里面的「已知会失败的方式」能帮你少踩坑。
2. **某步对不上就地重勘。** 锚点找不到、或点完页面反应和路书写的不一样 → 停下来自己找
   等价路径，走通之后**改写那一步**。后面的步骤**留着继续往下试**，别整体作废——
   UI 改版通常只动一个环节。哪里对不上，在 notes 里写清。
3. **已记的步骤走完还没到目标 → 继续往前勘。** 这时才是"自己找路"：允许试探性点击、
   换路径、靠页面变化推断业务逻辑，走错了退回来换一条。
4. **每验证通一步，当场用 upsert_playbook_step 只写这一小步**，绝不整份重写 playbook.md。
   跑批随时可能断——被人停掉、轮数耗尽、环境挂了——**当场写下的那几步断了也还在**，
   下次从那里接着勘；攒到最后写，一断就全丢。
   只写你真的走通过的路径，**不要写工具名、坐标、CSS selector**（资产要能换一套运行时照样用）。
   写不出【到位标志】说明这一步你还没验证过，先别记进去。
   路书沉淀不能压过业务目标：一旦收到轮数提醒，停止沉淀，先把业务流程走完。
